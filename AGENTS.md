# dc-transaction-service — Agent Instructions

Go (chi) service template. Auth boilerplate (register/login/logout) + user/role CRUD on schema `"User"`.

## Build & Run

```bash
go mod tidy && swag init
go run main.go -env local
```

Config: `application_<env>.json` (`secretkey`, `database`, `redis`, `state`, `jwt`, `log`).

## DB Migration & Seeding

Custom runner, no external deps. Subcommands after flags (default = serve):

```bash
go run main.go -env local migrate up        # apply pending migrations
go run main.go -env local migrate down [n]  # rollback last n (default 1)
go run main.go -env local migrate status    # applied/pending per migration
go run main.go -env local seed [name]       # all seeders, or one by name
```

- `migration/` — registry of `Migration{Version, Name, DBKey, Up, Down}`; `Version` is a `string` (timestamp-style, e.g. `"202611090001"` — sorts lexicographically) stored as `VARCHAR(32)` in `schema_migrations` (auto-created per DB). Each file registers via `init()` and declares its target `DBKey` from `cfg.Database` (writer, never replica). New migration = new file `migration/<version>_<name>.go`.
- `seed/` — registry of `Seeder{Name, DBKey, Run}`; seeders must be idempotent (`ON CONFLICT DO NOTHING`).
- Makefile shortcuts: `make migrate-up migrate-down migrate-status seed` (`ENV=`, `STEPS=`, `NAME=`).

## Routes (`app/controller/controller.go`)

- `/ping`, `/health/check`, `/health/check-db`; `/swagger` non-prod
- Auth/user slice (`auth_handler.go` / `auth_service.go` / `user_repository.go` + `query/user_queries.go`) on `"User".users`, under `/account`:
  - `POST /account/register` — `AuthRegister` (`RegisterRequest`: `first_name`, `last_name`, `username`, `email`, `role_id` (default 3=Staff), `password`; rejects duplicate username/email; stores `password` as SHA256 hex; `uid` generated by Postgres column `DEFAULT` — `INSERT` omits uid and reads it back via `RETURNING uid`)
  - `POST /account/login` — `AuthLogin` (`LoginRequest`: `username`, `password`; verifies SHA256, returns JWT `token` + `refresh_token` + user `data`)
  - `POST /account/logout` — `AuthLogout` (stateless; session/token managed client-side)
  - `GET /account/{uid}` — `UserGetByID`
  - `PUT /account/{uid}` — `UserUpdate` (`UserUpdateRequest`; empty `password` keeps old hash)
  - `DELETE /account/{uid}` — `UserDelete`
- Role slice (`role_handler.go` / `role_service.go` / `role_repository.go` + `query/role_queries.go`) on `"User".roles`, under `/role`:
  - `POST /role` — `RoleCreate`; `GET /role` — `RoleGetAll`; `GET /role/{id}` — `RoleGetByID`; `PUT /role/{id}` — `RoleUpdate`; `DELETE /role/{id}` — `RoleDelete`

The `transaction/` prefix seen in engine configs comes from the service base URL path.

## Auth

User + role tables (Postgres, schema `"User"` — quoted identifier, `user` is reserved — in db key `warehouse_db`):

```sql
CREATE TABLE "User".roles (
    id   INT PRIMARY KEY,
    name VARCHAR(32) NOT NULL
);

CREATE TABLE "User".users (
    uid        VARCHAR(16) PRIMARY KEY
               DEFAULT upper(substr(md5(random()::text), 1, 16)),  -- DB-generated uid
    first_name VARCHAR(64) NOT NULL,
    last_name  VARCHAR(32),
    username   VARCHAR(32) NOT NULL UNIQUE,
    email      VARCHAR(255) NOT NULL UNIQUE,
    role_id    INT NOT NULL REFERENCES "User".roles (id),
    password   VARCHAR(64) NOT NULL  -- SHA256 hex digest
);
```

- JWT helpers in `util/jwt.go` (`GenerateToken`/`ValidateToken`, HS256); claims in `app/model/entity/jwt_entity.go` (`uid` + `username`). Signing key = base64-decoded `secretkey`. `jwt.tokenexp`/`reftokenexp` config values are **hours**.
- Password hashing: `util/encryptor.go` `HashSHA256` (64-hex). `HashMD5` still exists for legacy reference.
- Seeded roles: 1=Superadmin, 2=Admin, 3=Staff. Seeded users: `superadmin`/`admin`/`staff` (password `admin123`/`admin123`/`staff123`).

## Databases & Clients

- Single Postgres DB `warehouse_db` — no replica. Schema `"User"` holds `users` + `roles`.
- Repositories are single-DB (`db` + `timeout` only); `InitDBConnection` still auto-aliases missing `<key>_replica` to the writer for any consumer that expects one.
- Redis (`config/redis.go` — connection pool helper, not yet wired in `main.go`)
